Commands cheat sheet

sf-core

Run only when you type them

  • /sf-startAsks one question, names the next command.
  • /sf-setupRecords tracker, commands, labels, docs layout and tools.
  • /sf-alignInterviews you to sharpen a plan.
  • /sf-planSpec, tickets, or a per-task implementation plan.
  • /sf-plan-reviewReviews a plan for scope, engineering, design, DX.
  • /sf-designDesign system, art direction, variants, refine and critique.
  • /sf-executeRuns a written plan task by task, then one fresh review.
  • /sf-implementBuilds one ticket or spec, no written plan.
  • /sf-qaTests the running app and fixes what it finds.
  • /sf-benchmarkMeasures page speed before and after a change.
  • /sf-devex-reviewTries your docs and onboarding live, scores the DX.
  • /sf-shipOpens or lands the PR, deploys, watches production.
  • /sf-release-docsBrings the docs in line with what shipped.
  • /sf-learnRetro on a session; capture or refresh lessons.
  • /sf-decision-mapMaps a big effort as decision tickets.
  • /sf-map-codebaseMaps an existing codebase into reference docs.
  • /sf-triageTurns issues and PRs into agent-ready briefs.
  • /sf-architecture-reviewFinds deeper modules, shows an HTML report.
  • /sf-guardAsks before destructive commands; freezes edits to one folder.
  • /sf-askWhich skill or flow fits your situation.

Also applies on its own

  • sf-tddA failing test before any implementation code.
  • sf-debugReproduce with a failing test, then fix.
  • sf-verifyNothing is done until fresh command output shows it.
  • sf-code-reviewStandards, spec and quality, reviewed in parallel.
  • sf-respond-to-reviewVerifies each review comment, then fixes or pushes back.
  • sf-doubt-checkFresh-context challenge of a decision in flight.
  • sf-source-checkGrounds decisions in official documentation.
  • sf-incremental-buildThin, verifiable slices.
  • sf-simplify-codeClearer code, same behaviour.
  • sf-frontend-uiDesign quality floor for every screen you build.
  • sf-module-designVocabulary for deep modules and seams.
  • sf-prototypeThrowaway code to answer a design question.
  • sf-glossaryKeeps the project's domain terms sharp.
  • sf-docs-and-adrsRecords decisions and documentation.
  • sf-worktreesAn isolated workspace for the work.
