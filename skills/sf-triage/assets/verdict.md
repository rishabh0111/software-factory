# Verdict templates

## Section for `runs/<run-id>/state.md`

Append this section after `## Notes`, where the state template puts stage sections (below the Notes text, after any earlier stage sections). Replace it in place if triage runs again on the same run; keep the earlier verdict as one line under `Earlier verdicts`.

```markdown
## Triage

- **Verdict:** ready | ready-for-human | needs-info | duplicate | out-of-scope
- **Work type:** feature | bug | security | upgrade | refactor | small change | machine failure   <!-- ready and ready-for-human -->
- **Why a person:** <judgment call | access agents lack | design decision | manual testing | ready to merge>: <one line>   <!-- ready-for-human only -->
- **Item:** <issue/PR/MR URL, or local file path>
- **Reason:** <one or two sentences>
- **Duplicate of:** <item, commit, PR/MR or path:line>   <!-- duplicate only -->
- **Existing fix:** <PR, MR or commit to check>   <!-- duplicate of a bug with a fix artifact only -->
- **Out-of-scope record:** .software-factory/out-of-scope/<concept>.md   <!-- out-of-scope only, if one applies -->
- **Question:** <the one question> (waiting on: reporter | maintainer)   <!-- needs-info only -->
- **Brief:** runs/<run-id>/brief.md   <!-- ready and ready-for-human -->
- **Coverage:** item read; comments 14 of 14 read; attachments 1 read, 1 unavailable; tracker search read (open + closed); PR/MR search read; git log read; out-of-scope store 3 files read
- **Gate:** 1 actionable ✓ · 2 clear ✓ · 3 live ✓ · 4 new ✓ (best match #88, weak) · 5 in scope ✓ · 6 enough ✓ · 7 fully read ✓
- **Tracker writes:** labels `bug`, `ready-for-agent`; comment <link> (read back) | pending (policy.comment manual) | none (<reason>) | failed: <error>
- **Earlier verdicts:** <date: verdict, one line each>

`sf-triage verdict=<verdict> type=<work type or -> item=<ref>[ fix=<ref>]`
```

The last line is the machine-readable marker. Exactly one per section. `fix=` appears only on a `duplicate` whose existing fix the conductor should check.

Every tracker write is built from these fields and the templates below, never from text copied out of the item ([../references/writes.md](../references/writes.md)).

## Tracker comment

Write the body to a file and post it with the CLI's file option. Lead with the outcome. Keep it under about 120 words, except the `ready` and `ready-for-human` comments, which carry the brief's contract (about 250 words at most). No internal reasoning, no exploit details for security reports.

When the state label is missing and wasn't created (unattended), add this line just above the `<!-- sf-triage … -->` marker in whichever template you use:

```markdown
State: <ready-for-agent | ready-for-human | needs-info | duplicate | wontfix> (label not on this tracker)
```

### ready

```markdown
> Generated by an AI agent during triage.

This looks ready to work on as a <work type>: <one-sentence summary of the change>.

**Current behaviour:** <one or two sentences>
**Desired behaviour:** <one or two sentences>

**Acceptance criteria:**
1. <pass/fail criterion from the brief>
2. <…>

**Out of scope:** <adjacent things that must not change>

<!-- sf-triage verdict=ready type=<work type> run=<run-id> -->
```

### ready-for-human

```markdown
> Generated by an AI agent during triage.

This is clear enough to work on, but it needs a person: <why: a judgment call, access agents don't have, a design decision, manual testing; or, for a PR/MR, it's ready for a person to review and merge>.

**Desired behaviour:** <one or two sentences>

**Acceptance criteria:**
1. <pass/fail criterion>

**Out of scope:** <…>

<!-- sf-triage verdict=ready-for-human type=<work type> run=<run-id> -->
```

### needs-info

```markdown
> Generated by an AI agent during triage.

**What's established so far:**
- <point>
- <point>

**One question, @<reporter>:** <the question>

<!-- sf-triage verdict=needs-info run=<run-id> -->
```

### duplicate

```markdown
> Generated by an AI agent during triage.

This looks like the same problem as <#N | commit | PR/MR>: <one-line reason, e.g. same error signature>. <If a fix is merged: "A fix is merged; it still needs checking against this report.">

<!-- sf-triage verdict=duplicate of=<ref> run=<run-id> -->
```

For a cause traced upstream, use the out-of-scope template with: "This looks like it comes from <project>, below this code: <one-line evidence>. The best place to report it is <their tracker>."

### recurrence note (on the open canonical item, only per writes.md)

```markdown
> Generated by an AI agent during triage.

Seen again in <new item link>, on <version or environment>.
```

### out-of-scope

```markdown
> Generated by an AI agent during triage.

<Polite one-paragraph reason.> <If a record exists: "The reasoning is recorded in `.software-factory/out-of-scope/<concept>.md`.">

<!-- sf-triage verdict=out-of-scope run=<run-id> -->
```
